# Feature Specification: 여행 코스 생성 및 날짜별 경로 표시

## Clarifications

### Session 2026-08-06

- Q: 날짜별 지도에서 이동 경로를 어떤 수준으로 표시해야 하는가? → A: 사용자가 교통수단을 선택한 실제 이동 경로를 표시한다.
- Q: 사용자가 선택할 수 있는 교통수단 범위는 무엇인가? → A: 도보, 자동차, 대중교통을 제공한다.
- Q: 사용자가 화면을 닫거나 나중에 다시 방문했을 때 여행 코스는 어떻게 처리해야 하는가? → A: 로그인 계정에 코스를 저장하고 같은 계정으로 다시 열면 자동으로 복원한다.
- Q: 하루 일정에 장소를 최대 몇 곳까지 등록할 수 있는가? → A: 날짜별 최대 10곳까지 등록할 수 있다.
- Q: MVP 서비스 지역은 어디인가? → A: 서울특별시로 한정하며 혼잡도 기능은 후속 범위로 제외한다.

## User Scenarios & Testing *(mandatory)*

### User Story 0 - 로그인 및 코스 동기화 (Priority: P1)

여행자는 카카오 또는 Google 계정으로 로그인하고, 자신이 만든 여행 코스를 저장하여 다른 안드로이드 기기에서도 이어서 편집한다.

**Why this priority**: 사용자별 코스를 안전하게 구분하고 여러 기기에서 복원하기 위한 선행 조건이다.

**Independent Test**: 한 계정으로 로그인해 코스를 만든 뒤 다른 지원 기기에서 같은 계정으로 로그인하여 동일한 날짜, 장소 및 방문 순서가 복원되는지 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 로그인하지 않은 사용자가 서비스에 진입한 상태에서, **When** 카카오 또는 Google 로그인을 완료하면, **Then** 해당 계정에 연결된 여행 코스가 표시된다.
2. **Given** 사용자가 한 기기에서 여행 코스를 편집한 상태에서, **When** 다른 지원 기기에서 같은 계정으로 로그인하면, **Then** 최신 여행 날짜, 장소 및 방문 순서가 복원된다.
3. **Given** 로그인이 실패하거나 취소된 상태에서, **When** 로그인 화면으로 돌아오면, **Then** 실패 또는 취소 사실과 다시 시도할 수 있는 행동이 안내된다.

### User Story 1 - 장소 검색 및 코스 추가 (Priority: P1)

여행자는 관심 지역과 키워드로 관광 장소를 검색하고, 결과의 장소명·주소·카테고리·좌표를 확인한 뒤 원하는 장소를 여행 코스에 추가한다. 이 과정을 반복해 후보 장소를 모을 수 있다.

**Why this priority**: 방문 장소를 찾고 선택하는 과정은 여행 코스를 만드는 모든 후속 작업의 출발점이다.

**Independent Test**: 지역과 키워드로 검색해 결과 정보를 확인하고, 한 곳 이상의 장소를 특정 여행 날짜의 코스에 추가하여 선택한 장소가 해당 날짜에 나타나는지 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 여행 날짜를 추가한 상태에서, **When** 서울 지역과 키워드를 입력해 장소를 검색하면, **Then** 서울 안에서 일치하는 각 결과에 장소명, 주소, 카테고리, 좌표가 표시된다.
2. **Given** 검색 결과가 표시된 상태에서, **When** 사용자가 장소와 등록할 여행 날짜를 선택해 추가하면, **Then** 해당 장소가 선택한 날짜의 마지막 방문 순서에 등록된다.
3. **Given** 한 장소가 특정 날짜에 이미 등록된 상태에서, **When** 사용자가 같은 장소를 같은 날짜에 다시 추가하려 하면, **Then** 중복 등록되지 않고 그 이유가 안내된다.
4. **Given** 검색 조건과 일치하는 장소가 없는 상태에서, **When** 검색이 완료되면, **Then** 결과가 없다는 안내가 표시된다.
5. **Given** 장소 검색을 완료할 수 없는 상태에서, **When** 사용자가 검색을 요청하면, **Then** 검색 실패 사실과 다시 시도할 수 있다는 안내가 표시된다.
6. **Given** 선택한 날짜에 장소 10곳이 이미 등록된 상태에서, **When** 사용자가 11번째 장소를 추가하려 하면, **Then** 장소가 추가되지 않고 날짜별 등록 한도와 해결 방법이 안내된다.

### User Story 2 - 날짜별 일정 편집 (Priority: P2)

여행자는 여행 날짜를 추가하고, 각 날짜에 등록된 방문 장소를 삭제하거나 방문 순서를 바꾸어 날짜별 일정을 구성한다.

**Why this priority**: 선택한 장소를 실제 여행 일정으로 만드는 핵심 편집 기능이며, 날짜별 경로 표시의 기준이 된다.

**Independent Test**: 두 개 이상의 날짜와 여러 장소를 준비한 뒤, 장소 삭제 및 순서 변경을 수행하여 각 날짜의 일정이 사용자의 최종 편집 내용과 일치하는지 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 여행 코스를 편집 중인 상태에서, **When** 사용자가 아직 등록되지 않은 여행 날짜를 추가하면, **Then** 비어 있는 해당 날짜의 일정이 생성된다.
2. **Given** 특정 날짜에 여러 장소가 등록된 상태에서, **When** 사용자가 방문 순서를 변경하면, **Then** 변경된 순서가 해당 날짜의 일정에 즉시 반영된다.
3. **Given** 특정 날짜에 장소가 등록된 상태에서, **When** 사용자가 장소를 삭제하면, **Then** 해당 장소가 그 날짜의 일정에서 제거되고 남은 장소의 상대적 순서는 유지된다.
4. **Given** 여행 날짜가 등록된 상태에서, **When** 사용자가 그 날짜를 삭제하면, **Then** 날짜와 그 날짜에 속한 방문 일정이 함께 제거되기 전에 결과가 명확히 안내되고 확인을 거친다.
5. **Given** 이미 등록된 여행 날짜가 있는 상태에서, **When** 사용자가 같은 날짜를 다시 추가하려 하면, **Then** 중복 날짜는 생성되지 않고 기존 날짜가 안내된다.
6. **Given** 사용자가 여행 코스를 편집한 뒤 화면을 닫은 상태에서, **When** 같은 계정으로 서비스를 다시 열면, **Then** 서버에 저장된 최신 여행 날짜, 장소 및 방문 순서가 자동으로 복원된다.

---

### User Story 3 - 날짜별 지도 경로 확인 (Priority: P3)

여행자는 날짜와 교통수단을 선택하여 그날의 방문 장소를 순서가 구분되는 마커로 확인하고, 선택한 교통수단을 기준으로 방문 순서대로 이어진 실제 이동 경로를 지도에서 본다.

**Why this priority**: 편성한 일정의 공간적 흐름을 시각적으로 검토하게 해 주며 MVP의 최종 사용자 가치를 완성한다.

**Independent Test**: 한 날짜에 순서가 정해진 여러 장소를 등록하고 그 날짜를 선택하여, 지도 마커와 경로가 일정의 장소 및 순서와 일치하는지 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 선택한 날짜에 두 곳 이상의 장소와 방문 순서가 등록된 상태에서, **When** 사용자가 도보, 자동차 또는 대중교통을 선택해 지도 경로를 확인하면, **Then** 모든 장소가 방문 순서를 식별할 수 있는 마커로 표시되고 선택한 교통수단을 기준으로 순서대로 연결된 실제 이동 경로가 표시된다.
2. **Given** 선택한 날짜에 장소가 한 곳만 등록된 상태에서, **When** 지도를 확인하면, **Then** 해당 장소의 마커는 표시되며 이동 구간이 없다는 점이 자연스럽게 드러난다.
3. **Given** 선택한 날짜에 등록된 장소가 없는 상태에서, **When** 지도를 확인하면, **Then** 경로 대신 장소를 추가하라는 안내가 표시된다.
4. **Given** 날짜별 경로를 불러오거나 계산할 수 없는 상태에서, **When** 사용자가 지도를 확인하면, **Then** 경로 조회 실패 사실이 표시되고 등록한 일정 자체는 유지된다.
5. **Given** 지도 경로가 표시된 상태에서, **When** 사용자가 장소 순서를 바꾸거나 장소를 삭제하면, **Then** 지도상의 마커 순서와 경로가 최신 일정과 일치하도록 갱신된다.

### Edge Cases

- 지역 또는 키워드가 비어 있거나 공백뿐인 경우 검색을 실행하지 않고 필요한 입력을 안내한다.
- 검색 결과에 주소나 카테고리 등 일부 표시 정보가 없는 경우, 해당 값이 제공되지 않았음을 표시하되 장소 선택 가능 여부는 유지한다.
- 서로 다른 검색 결과가 동일 장소를 가리키는 경우 장소의 고유 식별 기준에 따라 같은 날짜의 중복 등록을 막는다.
- 같은 장소는 서로 다른 날짜에는 각각 한 번씩 등록할 수 있다.
- 날짜 삭제 시 해당 날짜에 포함된 장소가 많더라도 삭제 범위가 날짜 전체임을 확인 전에 알린다.
- 첫 번째 또는 마지막 장소를 이동하거나, 장소가 두 곳뿐인 일정의 순서를 뒤집어도 유효한 순서가 유지된다.
- 경로 구성 중 일부 장소의 좌표를 사용할 수 없는 경우, 완전한 경로를 표시할 수 없음을 알리고 문제가 있는 장소를 식별할 수 있게 한다.
- 검색 또는 경로 조회 실패 후 다시 시도하더라도 이미 편집한 날짜와 장소 순서는 유지된다.
- 날짜별 장소가 10곳에 도달한 경우 추가 등록을 막고, 다른 날짜를 선택하거나 기존 장소를 삭제하도록 안내한다.
- 서울 밖의 지역이나 장소를 검색 조건으로 지정한 경우 MVP 지원 지역이 서울임을 안내한다.
- 여러 기기에서 같은 코스를 연속 편집하는 경우 서버에 마지막으로 정상 저장된 변경을 최신 상태로 표시하고 저장 실패를 사용자에게 알린다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사용자가 서울 지역과 키워드를 함께 지정하여 장소를 검색할 수 있게 해야 한다.
- **FR-002**: 시스템은 각 검색 결과에 장소명, 주소, 카테고리 및 좌표를 표시해야 하며, 값이 제공되지 않은 항목은 누락 사실을 명확히 표시해야 한다.
- **FR-003**: 시스템은 검색 조건과 일치하는 장소가 없을 때 결과 없음 안내를 표시해야 한다.
- **FR-004**: 시스템은 장소 검색이 실패했을 때 실패 사실과 재시도 가능한 행동을 사용자에게 알려야 한다.
- **FR-005**: 사용자는 여행 날짜를 추가할 수 있어야 한다.
- **FR-006**: 시스템은 동일 여행 코스 안에 같은 날짜가 두 번 생성되지 않도록 해야 한다.
- **FR-007**: 사용자는 여행 날짜를 삭제할 수 있어야 하며, 시스템은 해당 날짜의 모든 방문 일정이 함께 삭제됨을 사전에 알리고 확인을 받아야 한다.
- **FR-008**: 사용자는 검색 결과의 장소를 선택한 여행 날짜에 추가할 수 있어야 한다.
- **FR-009**: 새로 추가된 장소는 선택한 날짜의 기존 방문 장소 다음 순서에 배치되어야 한다.
- **FR-010**: 시스템은 동일한 날짜에 동일 장소가 두 번 등록되지 않도록 하고, 중복 시도 시 이유를 안내해야 한다.
- **FR-011**: 시스템은 동일 장소를 서로 다른 날짜에는 등록할 수 있게 해야 한다.
- **FR-012**: 사용자는 날짜별 일정에서 등록된 장소를 삭제할 수 있어야 한다.
- **FR-013**: 사용자는 같은 날짜에 등록된 장소의 방문 순서를 변경할 수 있어야 한다.
- **FR-014**: 시스템은 날짜별로 방문 장소와 확정된 방문 순서를 구분하여 유지해야 한다.
- **FR-015**: 사용자는 확인할 여행 날짜를 선택할 수 있어야 한다.
- **FR-016**: 시스템은 선택한 날짜의 모든 방문 장소를 지도에 마커로 표시하고 각 마커에서 방문 순서를 식별할 수 있게 해야 한다.
- **FR-017**: 시스템은 선택한 날짜에 두 곳 이상의 장소가 있을 때 방문 순서와 사용자가 선택한 교통수단을 기준으로 장소를 연결한 실제 이동 경로를 지도에 표시해야 한다.
- **FR-018**: 시스템은 장소가 한 곳인 날짜에는 해당 마커를 표시하고, 장소가 없는 날짜에는 장소 추가 안내를 표시해야 한다.
- **FR-019**: 시스템은 장소 추가·삭제 또는 순서 변경 후 표시되는 날짜별 지도 경로가 최신 일정과 일치하도록 해야 한다.
- **FR-020**: 시스템은 경로 조회가 실패했을 때 실패 사실과 재시도 가능한 행동을 알리고, 사용자가 등록한 일정은 보존해야 한다.
- **FR-021**: 시스템은 경로 표시에 필요한 좌표가 없는 장소가 있을 때 완전한 경로를 표시할 수 없음을 알리고 해당 장소를 식별할 수 있게 해야 한다.
- **FR-022**: 사용자는 한 여행 코스 안에서 날짜별 일정 편집과 지도 경로 확인을 반복할 수 있어야 한다.
- **FR-023**: 사용자는 날짜별 실제 이동 경로를 확인하기 전에 도보, 자동차 또는 대중교통 중 적용할 교통수단을 선택할 수 있어야 한다.
- **FR-024**: 시스템은 사용자가 같은 계정으로 서비스를 다시 열었을 때 서버에 마지막으로 정상 저장된 여행 날짜, 장소 및 방문 순서를 자동으로 복원해야 한다.
- **FR-025**: 시스템은 각 여행 날짜에 장소를 최대 10곳까지 등록할 수 있게 하고, 한도 초과 시 추가를 막으며 사용자가 취할 수 있는 행동을 안내해야 한다.
- **FR-026**: 시스템은 카카오 로그인과 Google 로그인을 제공하고 각 로그인 계정을 사용자별 여행 코스와 연결해야 한다.
- **FR-027**: 시스템은 로그인한 사용자의 여행 코스 변경을 서버에 저장하고 동일 계정으로 로그인한 지원 기기에서 최신 코스를 복원해야 한다.
- **FR-028**: 시스템은 로그인, 저장 또는 동기화 실패 시 실패 사실과 재시도 행동을 안내하고 마지막으로 정상 저장된 코스를 훼손하지 않아야 한다.
- **FR-029**: 시스템은 MVP 장소 검색 결과와 여행 코스의 장소를 서울특별시 안으로 제한해야 한다.

### Key Entities *(include if feature involves data)*

- **여행 코스**: 사용자가 계획 중인 한 번의 여행을 나타내며, 하나 이상의 여행 날짜로 구성된다.
- **여행 날짜**: 여행 코스에 포함된 특정 달력 날짜로, 중복되지 않으며 날짜별 방문 일정 하나를 가진다.
- **장소**: 검색으로 발견되는 방문 후보로, 고유 식별 기준, 장소명, 주소, 카테고리 및 좌표를 가진다.
- **날짜별 방문 일정**: 특정 여행 날짜와 장소를 연결하며, 그 날짜 안에서 중복되지 않는 방문 순서를 가진다.
- **날짜별 경로**: 선택한 날짜의 방문 순서에 따라 구성되는 지도 표현으로, 순서가 식별되는 장소 마커와 장소 사이의 이동 구간을 포함한다.
- **장소 검색 조건**: 사용자가 입력한 지역과 키워드의 조합이며 검색 결과 또는 결과 없음·실패 상태와 관련된다.

### Governance & Change Impact *(mandatory)*

- **Assigned Scope**: 길픽 첫 번째 MVP의 사용자 관점 기능 명세와 품질 체크리스트(`specs/001-trip-route-planning/`)가 범위에 포함된다.
- **Out-of-Scope Files**: 애플리케이션 코드, 기술 구성, 데이터 저장 구조, 외부 연동 구현 및 기존 프로젝트 산출물은 변경하지 않는다.
- **API Specification Impact**: 현 단계에서는 기술 스택이나 외부 연동 계약을 정하지 않으므로 범위 밖이다.
- **Database Structure Impact**: 현 단계에서는 저장 방식이나 데이터 구조 구현을 정하지 않으므로 범위 밖이다.
- **Compatibility and Rollback**: 사용자에게 배포되는 구현 변경이 없는 명세 단계이므로 해당하지 않는다. 명세 변경은 문서 이력으로 되돌릴 수 있다.
- **Core Business Logic**: 같은 날짜의 장소 중복 금지, 여행 날짜 중복 금지, 날짜 삭제 범위, 장소 추가·삭제·순서 변경, 빈 일정·단일 장소·복수 장소의 지도 표시, 검색 및 경로 조회 실패 시 일정 보존을 정상·경계·실패 사례로 검증해야 한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 대표 사용자 테스트에서 참여자의 90% 이상이 도움 없이 3분 이내에 지역·키워드 검색부터 장소 3곳을 한 날짜의 코스에 추가하는 작업을 완료한다.
- **SC-002**: 대표 사용자 테스트에서 참여자의 90% 이상이 두 날짜에 각각 3곳의 장소를 배치하고 원하는 방문 순서로 변경하는 작업을 첫 시도에 완료한다.
- **SC-003**: 검색 결과가 있는 정상 조건에서 사용자의 검색 요청 중 95% 이상은 2초 이내에 결과 또는 명확한 상태 안내를 보여 준다.
- **SC-004**: 경로 확인이 가능한 정상 조건에서 날짜를 선택하거나 일정을 편집한 경우의 95% 이상은 3초 이내에 최신 마커와 이동 경로를 보여 준다.
- **SC-005**: 검증된 모든 일정에서 지도에 표시된 장소와 순서가 선택한 날짜의 등록 일정과 100% 일치한다.
- **SC-006**: 중복 장소 등록, 결과 없음, 검색 실패, 경로 조회 실패의 검증 시나리오에서 100% 사용자가 현재 상태와 다음에 취할 수 있는 행동을 안내받는다.
- **SC-007**: 사용성 평가에서 참여자의 80% 이상이 날짜별 일정 구성과 지도 경로 확인 과정이 이해하기 쉽다고 평가한다.
- **SC-008**: 날짜별 장소가 1곳부터 10곳까지인 모든 검증 일정에서 장소 추가, 순서 변경 및 선택한 교통수단의 경로 표시가 정확히 완료된다.
- **SC-009**: 계정 동기화 검증에서 한 기기에 저장한 코스의 날짜, 장소 및 순서가 다른 지원 기기에서 같은 계정으로 로그인한 후 10초 이내에 100% 일치하게 복원된다.

## Assumptions

- MVP는 로그인한 한 명의 사용자가 자신의 여행 코스를 직접 편집하는 흐름에 집중하며 공동 편집, 공유 및 다른 사용자에 대한 권한 관리는 범위에서 제외한다.
- 장소는 먼저 여행 날짜를 만든 뒤 그 날짜에 직접 추가하며, 날짜가 정해지지 않은 별도 후보 목록은 MVP 범위에 포함하지 않는다.
- 여행 날짜는 달력 날짜 기준으로 관리하며 한 여행 코스 안에서는 중복될 수 없다. 날짜의 연속성이나 입력 순서는 제한하지 않는다.
- 새 장소는 선택한 날짜의 마지막 순서에 추가되고 사용자가 이후 순서를 바꿀 수 있다.
- 장소의 동일성은 검색 결과가 제공하는 안정적인 고유 식별 기준으로 판단한다고 가정한다.
- 경로의 목적은 선택한 교통수단에 따른 방문 순서의 실제 이동 흐름 확인이며, 소요 시간·거리 최적화, 자동 일정 추천 및 실시간 길 안내는 MVP 범위에서 제외한다.
- MVP는 카카오 또는 Google 계정으로 로그인한 사용자의 코스를 서버에 저장하고 여러 지원 기기에서 복원한다. 이메일·비밀번호 로그인은 범위에서 제외한다.
- 장소 검색과 경로 표시에 필요한 정보가 제공되는 운영 환경이 존재하되, 제공 방식이나 기술 공급자는 이 명세에서 결정하지 않는다.
- MVP 서비스 지역은 서울특별시이며 실시간 장소 혼잡도 표시는 후속 기능으로 제외한다.
